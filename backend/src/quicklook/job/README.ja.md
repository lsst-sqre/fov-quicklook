# Job

* Jobはquicklook生成パイプライン内の処理の単位。
  * パイプライン内でしか使用されない。
* quicklookの生成がリクエストされて初めてインスタンスが作られる
* quicklook生成やパイプライン内での優先順位を決定するために必要な情報を保持する。
* 次の情報を保持する
  * 処理対象visit
  * uuid
  * 優先順位をつけるための情報
    * waiting_users
      * 何人がこのvisitのために待機しているか
    * seq
      * インスタンスが作られた通し番号
* `waiting_users <= 0`のjobは各ステージに入るタイミングでスキップされる。
* `__new__`
  * 各visitに対して1つだけ作成される
