## coordinator のパイプライン実行モデル

`quicklook.utils.pipeline`モジュールは、非同期キューを繋いだステージ処理を記述するための軽量なパイプライン実装を提供する。

### Stage

* `Stage.process`
	* 入力1件を非同期で処理し、次ステージへ渡す値を返す。
	* 例外として`Skip`を送出すると、そのアイテムはそれ以降のステージと`on_finish`に渡されない。
* `parallel`
	* 同一ステージを同時に実行するワーカー数を制限する。
	* テストでは最大同時実行数が設定値を超えないことを検証している。
* `item_picker`
	* 入力バッファからどのアイテムを取り出すかをカスタマイズできる。
	* 例えば優先度の高いジョブを`max`で選択する、といった戦略が可能で、テストでは最新アイテム優先の挙動を確認している。
* `on_enter` / `on_exit`
	* 各アイテムの処理前後に補助処理を挿入できる。監視やリソース確保に利用する。

### Pipeline

* `Pipeline.append`
	* ステージを直列に追加し、型パラメータに応じて入力・出力型が更新される。
* `Pipeline.on_finish`
	* 最終ステージの出力を受け取り、完了後処理を非同期に行う。
	* 内部では await されるため、ここでの非同期処理が完了するまでパイプラインは次の完了通知を処理しない。
* `Pipeline.run`
	* コンテキストマネージャでワーカー群を起動し、`push`/`cancel`を持つハンドルを提供する。
	* コンテキスト終了時にはすべてのタスクをキャンセルしてクリーンアップする。

### テストでカバーしている観点

* 直列ステージの基本的な処理フロー
* `on_enter`/`on_exit`フックの呼び出し順序
* `Skip` 例外でのスキップ挙動
* `parallel` 指定による同時実行数の上限
* `item_picker` による優先度制御
